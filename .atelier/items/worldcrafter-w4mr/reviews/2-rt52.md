## Finding 2: Ordinary query results have no clickable record or scene references
Recommendation: fix now
Was: 1-08b5.2
Response: fixed in 9cfbadb
Now: kept

The fix adds working links for `show`'s subject and the string refs under `ref`/`on`, plus scene IDs under `scene`. The new component test correctly follows the ordinary `show(actor:mara)` result. That part of the response holds.

`app/src/agent/inspect.ts:316-328` still drops other reference shapes already returned by the supported queries. It recognizes neither stored `Ref` objects (`{ kind, id }`) nor strings in a reference array, whose key is discarded by `visit(item, null)`. Two reproductions with real tool results from the existing lighthouse fixture:

- `show({ref:"fact:oil-runs-out"})` returns `data.record.about: [{kind:"count",id:"oil"},{kind:"object",id:"lamp"}]`, and its readable lines explicitly name both records. `callNamed` returns only `fact:oil-runs-out`; neither `count:oil` nor `object:lamp` can be opened from the result.
- `readerOrder({before:"confession"})` returns `data.withheld: ["open-question:why-leave"]`. `callNamed` returns the scene and told refs but drops that withheld ref, so the writer cannot follow the held-back question named in the result.

DESIGN.md's Tool trace rule still requires those named records to be references above the raw result. Extend the extractor for these existing typed result shapes, validating and deduplicating refs as it does now, and add regression coverage for both. This is the remaining portion of the original query-reference finding, not a request to infer links from arbitrary prose.
