## Finding 1: Preserve a deliberately edited model when the profile has not changed
Recommendation: fix now

Independent validation after taking over this review: `bun run check` again passed all 1,175 tests. A separate in-memory generator probe with stub `fetch` and an unchanged profile reproduced the same problem: `sendEdited` sent `per-request-model`, but `segmentRequest` showed `profile-default` with `retargeted: true`, and ordinary Regenerate sent `profile-default` with `retargeted: true`. This confirms the finding below without relying on the earlier component probe.

`app/src/llm/client.ts:163` treats any difference between `request.body.model` and `profile.model` as a profile change. `current` in `app/src/generate/generator.ts:375` therefore retargets an intentionally edited revision, and `retarget` overwrites its model at `app/src/llm/client.ts:146`. Both the segment's Request action and its default Regenerate action go through this path.

Reproduction with the app fixture: leave the profile model at `stub-model`, open a new request, change only the Parameters JSON model to `writer-chosen-model`, and Send edited request. The first request correctly sends `writer-chosen-model`. Without changing the profile, open the resulting segment's Request: its Parameters now show `stub-model` and the slip incorrectly says the model settings changed. Close the slip and press Regenerate: the next request sends `stub-model`. My component probe expected the originally chosen model and received `stub-model` instead. Before this change, the unchanged URL left that revision intact.

Comparing the current profile to an editable request body cannot establish that the profile changed. Preserve explicit request edits when the profile is unchanged while retaining the required retargeting for actual profile model changes at the same URL. Add coverage for an edited model surviving both Request and Regenerate alongside the existing profile-change test. Keeping the explicit request-ID APIs unchanged does not protect this case, because the shipped caption actions do not pass such an ID.
