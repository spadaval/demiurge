## Finding 5: Keep text typed during a new topic's first model turn
Recommendation: fix now

`app/src/app/talk.ts:282-285` deletes the entire `unsent` entry after awaiting the first turn whenever the topic was stored. The composer remains editable during that turn (`app/src/app/topics.tsx:921-926`), so this deletes any next message the writer has typed while waiting. The sent text was already cleared at line 276; the later deletion removes writing that was never sent.

In a component scenario, I opened New topic, named it Lamp, sent First question, held the stub response, and typed My next thought while I wait into the still-editable composer. After releasing the response, the composer value was empty. A direct service reproduction likewise showed the new text in `unsent` before completion and an absent entry afterward.

Remove only the completed draft's metadata at that point, preserving any composer text entered after Send. Add a component regression that types the next message while the first response is pending and checks it remains after the draft becomes a stored topic.

## Finding 6: Do not show a running turn's writer message twice after navigation
Recommendation: fix now

`app/src/app/topics.tsx:800-806` unconditionally renders `running.message` as another writer turn. On returning to a running stored topic, `TopicPage` calls `talk.open`, which loads the writer message that `take` already persisted. `TopicSheet` renders that stored message at lines 655-657 and then renders it again through `RunningTurnView` at lines 658-659. Renaming during a turn also reloads the topic view and reaches the same duplication.

A component scenario raised a topic, sent Which is it?, held the response, navigated to the inbox and back, and then read the turns. The sheet showed the opening model message, You / Which is it?, You / Which is it?, and the running model placeholder. The assertion that the sent body appears once failed with length 2. The duplication disappears when the response finishes, but makes ordinary navigation display an incorrect conversation while it runs.

Give the optimistic writer turn a stable relationship to its persisted message, or otherwise render it only until that message is present in the loaded view. Do not deduplicate by text, since repeated writer messages are valid. Cover navigating away and back while a response is pending.
