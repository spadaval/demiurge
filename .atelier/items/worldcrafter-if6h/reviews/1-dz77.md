## Finding 1: Passage-topic gloss notes cannot follow Gloss Note grammar without a layer
Recommendation: fix now

[DESIGN.md:380](/home/supadava/.t3/worktrees/demiurge/t3-c41fd8de-c523b24692a09fbc/DESIGN.md) says passage topics appear as gloss notes of kind "Talk" with a neutral key and head in `ink-2`, "follow the Gloss Note grammar and the Paint-Only Rule", and "this section adds no layer hue for them".

The Gloss Note grammar at [DESIGN.md:333](/home/supadava/.t3/worktrees/demiurge/t3-c41fd8de-c523b24692a09fbc/DESIGN.md) is: key and head in the layer's hue, and "Notes and ticks appear only when their layer is on: the note fades, the tick draws." Paint-Only at [DESIGN.md:280](/home/supadava/.t3/worktrees/demiurge/t3-c41fd8de-c523b24692a09fbc/DESIGN.md) is a rule about layers. There is no Talk layer, and default layer state is Speakers only.

An implementer can read this as always-visible notes (no layer to turn off) or as Notes-layer-gated notes (grammar, with hue swapped for `ink-2`). The first hides no topics and needs a sentence that they are not layer-gated. The second hides every passage topic until Notes is on, which fights `worldcrafter-rxvy`'s "surfaced unobtrusively". Either sentence is enough; the two rules cannot both apply as written.

This is Done when 2 (Named Rules consistent with the new sections). `worldcrafter-lhh3` leaves scene-sheet surfacing to `rxvy`, but the contradiction lives in the document those items check.

## Finding 2: Composer Send and next-turn slip Send are both specified as the one primary
Recommendation: fix now

[DESIGN.md:301](/home/supadava/.t3/worktrees/demiurge/t3-c41fd8de-c523b24692a09fbc/DESIGN.md) lists one primary per surface, including "Send in a request or agent slip" and "Send in a topic's composer". The composer at [DESIGN.md:392](/home/supadava/.t3/worktrees/demiurge/t3-c41fd8de-c523b24692a09fbc/DESIGN.md) has Send as its primary. The next-turn slip at [DESIGN.md:413](/home/supadava/.t3/worktrees/demiurge/t3-c41fd8de-c523b24692a09fbc/DESIGN.md) also has Send as its primary. Opening Context puts both on screen at once.

On a scene sheet those two primaries are different actions: Generate next opens the slip, Send on the slip fires. Here both controls are named Send. `worldcrafter-lhh3` and `worldcrafter-w4mr` will each implement one. Unspecified: whether they are the same action, whether composer Send includes slip edits ("Edits apply to the next turn only"), and which primary remains if only one may show.

The running-turn case is the same hole. The topic head gives Stop as a text action ([DESIGN.md:391](/home/supadava/.t3/worktrees/demiurge/t3-c41fd8de-c523b24692a09fbc/DESIGN.md)). The shipped request slip replaces Send with a Stop button (`context-viewer.tsx` `sending` / `onStop`). A running turn's slip is neither "next turn" nor "a past turn's slip" (no Send). Say what the slip shows while the turn runs.

A spec that matches the talk page: Send lives on the composer and submits the composer text plus any next-turn slip edits; the next-turn slip has Discard edits and no Send; Stop stays the text action on the running turn's head. Prose generation keeps Send (and Stop-in-place-of-Send) on the request slip, which has no composer.
