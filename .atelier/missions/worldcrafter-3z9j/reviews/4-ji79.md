## Finding 1: Receipt-order LWW lets a stale device that reconnects overwrite newer prose with no snapshot
Recommendation: fix now
Was: 3-pyts.6
Now: fixed
`ji5d` Goal (`.atelier/items/worldcrafter-ji5d/item.md` lines 25–32) replaces receipt-order LWW with pull-then-push and optimistic `baseRev` against a Worker `serverRev`. A stale reconnect whose `baseRev` does not match is rejected with the server record or tombstone; it cannot stamp a later `syncedAt` and overwrite the laptop's already-synced passage. Per-record `{ serverRev, dirty }` lives in device-local sync metadata, outside synced world records. Plate `Document` conflicts snapshot the losing local draft before adopting the server revision (rejected push or pull over a dirty document). Non-document records let the server revision win; a stale edit does not resurrect a newer tombstone; an explicit save after pulling the tombstone recreates with that tombstone's `serverRev` as `baseRev`. Test (b) is the Round 3 sequence and requires both the laptop passage and the phone edit to remain recoverable. The mission success criterion now names this protocol.

Using a monotonic `serverRev` rather than `syncedAt` as the base token is stricter than the suggested fix and still keeps Worker-stamped `syncedAt` for the clock-skew test.
