## Finding 13: qizl's round-trip check leaves out the legacy collections, so "lossless whole world" can pass while user data drops
Recommendation: fix now

The mission's second success criterion and qizl's Goal both say the whole-world export includes "active legacy collections". This mission keeps those stores in use: `worldEntries`, `outlines`, `timelines` and snapshots (`app/src/storage/types.ts`). qizl's first Done when line lists only "documents, annotations, stored requests, and all story-bible collections". An export that drops world entries, outline books and chapters, and the time store's timeline passes that check. Importing such a file into an empty store loses the world entries for places and cultures, the chapter titles and the story time that the current app shows. "Active legacy collections" is also never defined.

Fix: in qizl's Goal and first Done when line, name the collections the export carries: `worldEntries`, `outlines`, `timelines`, and snapshots, or say why snapshots are left out. Put each in the round-trip fixture.
